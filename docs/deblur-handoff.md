# 被写体ブレ補正：作業の引き継ぎ

2026-10-25 時点。ブランチ `claude/subject-deblur`（`claude/kind-hopper-jnlyd3` の a84be3b から分岐）。アプリへの組み込みはまだ。調べた結果と試作のスクリプトだけ。

## ねらい（依頼）
- シャッター速度による被写体ブレ（手だけ速く動いてぶれる、など。手ぶれ補正ではない）を補正する。ぶれている所だけ直す。
- 実用に耐える自然さ。極端なブレ（回るスカートなど）までは求めない。重くてよい、「残り○%」のバーを出す。
- 実写真で 100% 拡大して確かめる。数値だけで合格にしない。終わったら、暗所補正（ノイズ除去・明るさ）・美肌など・書き出しと重ねて確かめる。
- ユーザーの判断（2026-10-25）：**AI（学習済みモデルを端末内で動かす）で進める**。初回に数十MBのダウンロードがあってよい。

## 試す写真（E:\DCIM\100CANON、10/24 分。リポジトリには入れない）
- IMG_9345（主）：1/100 秒・191mm・ISO1600、縦 3456×5184。ユーザーの見立てでは「手だけ」ぶれている。測ると、ティアラの光の点は 15〜20 画素の縦にななめの線（顔もわずかに）、左手・胸の前の手は 30 画素以上、スカートは回転でもっと大きい。
- ほか（コーディネーターより）：9395（手・髪・スカートがぶれ、顔はくっきり）、9316（腕）、9242（髪）、9328（脚）。プロジェクトの `test-photos/` にもある。

## わかったこと
1. **AI なしの計算（ブレの形を仮定して逆算、TV 正則化の逆畳み込み）**：顔で試したが、ノイズが減るだけでシャープさはほとんど戻らない。強めると縞が出る。ぶれている所の自動検出（勾配の自己相関、輪郭の幅）も、カーテンのひだや平らな所と区別できなかった。→ 不採用。`scripts/deblur-proto/classic_deconv.py`。
2. **NAFNet GoPro width32**（MIT、1711 万パラメーター、fp32 で 69MB）：
   - ISO1600 のノイズのまま入れると、ノイズを「ぶれた模様」と見て肌・背景に横縞を作る。**先にノイズを取る（暗所補正のノイズ除去・明るさの後）と顔・歯・ティアラが少しくっきりする**。
   - 大きなブレ（手）は元の大きさでは直らないが、**1/2 に縮めて当て、直した差分だけを元の大きさに足す**と、胸の前の手の指がはっきりした（胸の肌に木目のような筋が出るのは要対処）。
   - **致命的な問題：入力によって出力が壊れる**（色の砂嵐になる）。平らな所（カーテン）を多く含む 256×256 のタイルで多い。IMG_9345 を 1/2 にしたとき、ノイズ除去後でタイルの 4 割、元のままだと 9 割近く。同じ色の平らなタイル（0.6, 0.4, 0.25）でも壊れる。PyTorch と onnxruntime で同じ結果なので、計算の誤りではなくモデルの性質（エンコーダー最深段の 28 ブロックで、チャンネル注意 SCA の値が数百に暴走 → 残差が発散）。普通の屋外写真（IMG_9507 を 1/4）では 24 タイルとも正常。
   - 試した対策：SCA を ±40 で止める（壊れ方が小さくなるだけ）、左右・上下反転、転置、明るさ 0.85・0.6 倍（0.6 倍がいちばん効くが、それでも 6/77 タイルはどれも壊れる）、TLC（NAFNetLocal）で大きなタイル（もっと悪い）。壊れたタイルは差が 2 以上（正常は 0.3 以下）とはっきり分かれるので、**検出は簡単**。
   - ONNX への書き出しはできた（opset 17、256×256 固定、69MB）。
3. **FFTformer RealBlur-J**（MIT、1656 万パラメーター、66MB）：壊れない（顔・手のタイル 0/32）が、**ほとんど直らない**（顔・手とも見た目の差がわずか）。CPU の PyTorch で 256×256 が 1 枚 18 秒と遅い。torch.fft を使うので ONNX・Web で動かすのも手間。GoPro の重み（`pretrain_model/fftformer_GoPro.pth`、リポジトリ内）は未試験。

## 次にやること（案）
1. 方式を決める。いちばん見込みがあるのは NAFNet GoPro を「ノイズ除去・明るさの後に、1/2（大きなブレは 1/4）に縮めて、人物の範囲だけに当て、壊れたタイルを見つけたら変形（0.6 倍など）でやり直し、だめならそのタイルは当てない（元のまま）」。差分を元の大きさに足す。壊れた・壊れかけの所が混じらないかを 100% で必ず見る。
2. ほかの候補も試す価値あり：FFTformer の GoPro 重み、Uformer・Stripformer（ライセンスと重みの有無を確認）、NAFNet GoPro width64（安定するかもしれないが 270MB と大きい）。ライセンスが書かれていない MIMO-UNet は使わない。
3. アプリへの組み込み：onnxruntime-web（WebGPU があれば使う、なければ WASM）を Worker で。モデルは fp16 にして約 35MB、初回だけ読み込みキャッシュ（MediaPipe と同じ扱い。`sw.js` のオフライン対応も）。編集の値 `adj.deblur`（0〜100）、`hqKey` に入れる。順番は「ノイズ除去 → 明るさ → ブレ補正 → 粒（film grain）」（粒の後に当てると粒が筋になる）。書き出し（`fullres.js`）でも同じ順で。
4. 終わったら、暗所補正＋美肌＋明るくブラシ＋露光量＋書き出しを IMG_9345・9395 で重ねて確かめる（`docs/lowlight-handoff.md` の「ほかのレタッチとの重ねがけ」と同じやり方）。

## 試作の動かし方
`scripts/deblur-proto/`（写真・学習済みデータ・ONNX は .gitignore で除外）。
```
cd scripts/deblur-proto && sh setup.sh          # PyTorch(CPU)・gdown・学習済みデータ
python tiled.py in.png out.png 256 0.5           # NAFNet、256 のタイル、1/2 に縮めて差分を足す
python scan.py in.png 0.5                        # 壊れるタイルの数を数える（差 0.6 超）
python variants.py in.png 0.5                    # 反転・明るさ倍で壊れ方が変わるか
SCA_CLAMP=40 python scan.py in.png 0.5           # SCA を止めた版
python fftformer_tiled.py in.png out.png 1       # FFTformer RealBlur-J
```
暗所補正をかけた入力は `node scripts/lowlight-eval.mjs in.rgb 3456 5184 out.rgb 50 50` で作る（`docs/lowlight-handoff.md`）。この PC では IMG_9345 全体で約 85 秒。

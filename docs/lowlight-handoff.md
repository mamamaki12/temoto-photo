# 暗所補正・ノイズ除去・ブレ補正：作業の引き継ぎ

2026-10-24 時点。ローカルで続けるためのメモ。公開版には未反映。

## ねらい（依頼）
- 暗い写真を、画質やノイズを悪くせずに明るくする。スマホが重くなってもよい。進捗は「あと何%」のバーで出す。
- 一眼で ISO を上げすぎて乗ったノイズを除去する。
- 手ブレ・手だけの動きブレも補正する。
- 実用に耐える自然さ。極端に大きなノイズ・ブレまでは求めない。
- 対象は、暗い会場で撮った人物写真（全身のブレ、手だけのブレ、高ISOのノイズ）。

## 同じ写真での比較（3.jpg、5.3倍に明るく）
- Codex：カーテンの残りノイズ 0.8%、7秒。ざらつきはほぼ消えるが、肌・布が少しのっぺり。赤緑のまだらが残る。
- 試作：残りノイズ 2.5%（元 3.7%）、23〜34秒。ざらつきが残り、全体が平坦。細部は残る。
- 試作の弱点：ノイズの量を実際より小さく測る（粒が 2〜3 画素で、3×3 のフィルターでは拾えない）。
- 注意：添付写真は 1333×2000 に縮小済み。実際のカメラ画像ではノイズの出方が違う。

## 足りない点
1. ノイズ除去が編集画面につながっていない（Codex の GPU スライダーはノイズを取らずに倍率を掛ける）。
2. ノイズ量が手動の固定値（Codex）／測り方が不十分（試作）。
3. 粒の大きさが 1 種類しか見られていない。高ISOの大きな粒が残る、または細部が薄くなる。
4. 色ノイズ（赤緑のまだら）の除去がない。
5. ブレ補正は未着手（全体ブレ・部分ブレとも）。
6. 明るさが単純な倍率。全体の流れと細かい模様を分けた補正（試作にあり）が未統合。
7. 原寸（2400万画素以上）を編集画面で通す経路がない（Worker は 400 万画素、比較画面は 1600 万画素まで）。
8. iPhone 実機での確認がない。

## 試作 `lowlight.js` の中身
- `noiseProfile`：明るさごとにノイズ量を測る（要改善）
- `nlm`：Non-Local Means（輝度で似た模様を探し、3 チャンネルをまとめて平均）
- `denoise`：2×2 で縮めた絵でもノイズを取り、大きな粒を除く（3 段）
- `guided`：色差を輝度の輪郭に沿ってならす
- `enhance`：上を実行したあと、明るさの全体の流れだけを持ち上げ、細かい模様は残す（自動倍率、白の押さえ）
- DOM を使わない純粋な計算。Worker・Node のどちらでも動く。

試す手順（Node 18 以上、写真は PPM に変換）：
```
python3 -c "from PIL import Image; Image.open('photo.jpg').convert('RGB').save('in.ppm')"
node scripts/lowlight-proto.mjs in.ppm out.ppm nr=1      # nr: ノイズ除去の強さ、gain=: 明るさの倍率（省略で自動）
```

## 次にやること（提案の順）
1. `codex/photo-restoration-core` をこのブランチにマージする（`app.js`・`engine.js`・`state.js` の競合に注意）。
2. 試作から移す：ノイズ量の自動測定（測り方を直す）、複数段のノイズ除去、色ノイズ除去、全体と細部を分けた明るさ補正。Codex の Worker・帯分割に載せ、編集画面の「ノイズ軽減」「暗い写真を明るく」からつなぐ。
3. ノイズを先に取ってから明るくする順序にする（今のスライダーは逆）。
4. 原寸の経路と進捗バーを通す（読み込み → ノイズ測定 → 除去 → 明るさ → 書き出し）。
5. ブレ補正の試作：全体ブレ → 手だけのブレ（場所ごとにブレ方を推定。AI モデルは使わない前提で、効果の限界を先に確認）。
6. 実際の原寸写真で、肌・髪・レース・指を 100% 拡大で確認。iPhone 実機でメモリと時間を確認。

## 検証のしかた
- 数値：平らな所（カーテン）の「細かい成分の標準偏差 ÷ 平均の明るさ」を、処理前後で比べる。
- 目視：顔・レース・髪を 100% 拡大で並べて比べる。数値だけで合格にしない。
- 個人の写真はリポジトリに入れない。手元に原寸の元ファイルが必要（Codex 側の検証用 4 枚は、Codex の作業環境にだけある）。

# 暗所補正・ノイズ除去・ブレ補正：作業の引き継ぎ

2026-10-25 時点。ブランチ `claude/kind-hopper-jnlyd3`。公開版には未反映。

## ねらい（依頼）
- 暗い写真を、画質やノイズを悪くせずに明るくする。スマホが重くなってもよい。進捗は「あと何%」のバーで出す。
- 一眼で ISO を上げすぎて乗ったノイズを除去する。
- 被写体ブレ（シャッター速度による。手だけ速く動いてぶれる、など）も補正する。手ぶれ補正ではない。
- 実用に耐える自然さ。極端に大きなノイズ・ブレまでは求めない。
- 肌は自然な色で、明るく。色味は、同じ舞台を明るく撮った写真（IMG_9228 など）に近づける。

## いまの仕組み
編集画面の「おまかせ → 自動補正 → 暗い写真を明るく」の 2 つのスライダー（ディテールの「ノイズ軽減」も同じ値）。

| ファイル | 役割 |
| --- | --- |
| `restoration-lowlight.js` | 計算（DOM なし）。ノイズ量の測定 → 点状ノイズの除去 → 3 段の Non-Local Means → 色ムラ除去 → ざらつきを 2 割戻す → 明るさ（ベースとディテールを分ける） |
| `restoration-worker.js` | Worker。`type: 'lowlight'` の帯を処理する（以前の `restoreLinear` もそのまま） |
| `restoration-photo.js` | `enhancePhoto`：中央 2048×2048 でノイズを測り、縮めた絵で明るさの曲線を決め、帯（上下 48 行の余分つき）を最大 4 つ（iPhone は 2 つ）の Worker で同時に処理。`enhanceCanvas`：編集用の大きさの写真に当てる |
| `app.js` | スライダーから手を離して 0.4 秒たつと Worker で計算。写真の下に「残り○%」のバー。計算中は GPU の簡易版で表示し、できたら差し替える（GPU の簡易版は二重にかけない） |
| `fullres.js` | 元の大きさの書き出しでは、元の写真に帯ごとに当てて GPU に送る（美肌・修復はその後）。進捗の前半が暗所補正 |

- スライダーの値：ノイズ軽減 50 で標準の強さ（`nr = 値/50`）、明るさ補正 50 で自動の狙い（ベースの平均がリニアで 0.16、最大 12 倍）。
- 色：明るい所（上位 5%）から照明の色を測り、色かぶり（赤紫）だけ取って、色温度（電球の琥珀色）は残す。色の濃さは元のまま明るくする。
- 帯に分けても、写真全体を一度に処理したのと同じ結果（実写真の切り出しで差 0、テストあり）。

## 実写真での確認（手元の元写真、E:\DCIM\100CANON の 10/24 分。リポジトリには入れない）
- 主に IMG_9348（白い衣装）と IMG_9321（青い衣装）。Canon EOS Kiss X7i、ISO1600、5184×3456。色の参考は IMG_9228（同じ舞台・明るいとき）と IMG_9507（屋外）。
- 顔・髪・指・レース・スカート・カーテンを 100% で並べて確認した。直したこと：
  1. 明るくすると色が抜けて灰色になる → 色の濃さを保つ
  2. 黒い小さな点が残る（2〜3 画素ににじんだ点）→ 元の大きさと 1/2 の大きさで点を探して消す
  3. 肌・指・レースがろう細工のようになる → 取ったざらつきを 2 割戻す、段ごとの強さを控えめに
  4. 白い衣装が飛ぶ → 明るい側の押さえ（上位 0.1% の 1.1 倍を白に）
  5. ドライ・赤紫に見える → 照明の色を戻しすぎていた。色かぶりだけ取り、琥珀色は残す
  6. ノイズ量の測り方：8×8 の区画では大きな粒を 3 割小さく測っていた → 16×16 の区画に（テストあり）
- 時間（この PC、Chromium）：編集用（3336×5004）で約 28 秒、元の大きさの JPEG 書き出しで約 38 秒。

試す手順（Node 18 以上。写真は PIL で RGB を並べただけのファイルにする）：
```
python -c "from PIL import Image, ImageOps; im=ImageOps.exif_transpose(Image.open('IMG_9348.JPG')).convert('RGB'); open('in.rgb','wb').write(im.tobytes()); print(*im.size)"
node scripts/lowlight-eval.mjs in.rgb 3456 5184 out.rgb 50 50   # ノイズ軽減・明るさ補正（0〜100）
```

## 残っていること
1. 肌の色相は、まだ IMG_9228 より少しピンク寄り（9348 の頬で色相 10°、9228 で 22°）。ユーザーの判断待ち。
2. iPhone 実機でのメモリ・時間の確認がない（Worker 2 本・帯 1 本あたり 100MB くらいの見込み）。
3. 一覧の見本とグリッド（`renderToCanvas` を直接使う所）は GPU の簡易版のまま。書き出し（1 枚・まとめて）は補正済み。
4. RAW は 8bit にしてから補正している（16bit の残差は使わない）。RAW のノイズ除去との二重がけは未確認。
5. 被写体ブレの補正は未着手。試すなら IMG_9345（ユーザー推薦）。

## 検証のしかた
- 目視：顔・レース・髪・指を 100% 拡大で並べて比べる。数値だけで合格にしない。
- 色：同じ舞台の明るい写真（IMG_9228）のカーテン・白い衣装・肌と、色相・彩度を比べる。
- 個人の写真はリポジトリに入れない。

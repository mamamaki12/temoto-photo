# リップ・歯の範囲の自動化 引き継ぎメモ（2026-10-25）

ブランチ: `claude/lip-teeth-auto`（`claude/kind-hopper-jnlyd3` から分岐。PR 未作成）。残りの 2 つを直した続きは `claude/project-thread-u69pia`

## できたこと
- リップ・歯とも、なぞった所・タップした所は「目印」。範囲はアプリが自動で決める（`app.js` の `fxAction`、`op.whole = true` と `op.lips`）。
- `skinseg.js` の `findMouth`: 目印のまわりを狭い方から（目印の大きさの 5・10・20・40 倍）切り出して FaceLandmarker に渡す。舞台・集合写真の小さな顔も見つかる（10/24 の写真で試した 35 個すべて見つかった）。最後に写真全体でも探す。
- `brushfx.js` の `segmentMouth`: 口のまわりを 肌・唇・歯・口の奥 の 4 つに塗り分ける。
  - AI の輪郭は目安（prior）。確かな所から各クラスの色（Y・Cb・Cr）の正規分布を 2 つずつ（明るい／暗い）覚え、画素ごとの事後確率を出し、となりと揃うよう 4 回ならす（mean-field）。分けた結果で分布を作り直してもう 1 回。
  - 歯の種（確かな歯）は内側の輪郭の中だけから取る（唇のつやを拾わない）。口の中の明るい方 6 割・肌と比べて赤みが少ない所。種が少なければ歯なし（口を閉じている）。
  - 上の歯は内側の輪郭の上の線より上にはほぼ出ない、として歯の prior を下げる（日の当たった上唇対策）。
  - 歯は、確かな歯と唇の赤み（緑÷赤）の中間で切る（歯ぐき・濡れた下唇）。暗い写真は境目を唇寄りにして広くならす。
  - 小さな歯のかたまりは、口の中にあって、大きいか口の奥（暗い所）に接しているものだけ残す。
- 歯の白さ: 黄ばみを、まわりの肌の色の 0.55 倍の淡い色に寄せる（照明の色は残す）＋少し明るく。
- テスト: `tests/unit/mouth.test.js`（作りものの口）、`tests/e2e/photo-ai.spec.js`（歯のタップ・閉じた口）。単体 58・画面 69 すべて通過。

## 直したこと（2026-10-25、クラウド）
1. 口の端の影に入った奥の歯（IMG_9471 の 2 人目）: 歯の色の分布を、影で 0.7・0.5・0.35 倍に暗くした色でも測る（`shadeLike`）。内側の輪郭のあたりだけ・明るい写真だけ（暗い舞台では暗い唇と見分けがつかない）。上の歯の陰になった下の歯も拾えるようになった。
   - いちばん奥の、ほぼ真っ暗で赤く写った歯（明るさ 32 ほど）は、口の奥と色が同じで拾えない。白くしても不自然なので、対象外とした。
2. 日の当たった上唇（IMG_9516 の左端の人）: 歯と唇を分ける赤み（緑÷赤）の境目を、写真全体の値でなく、その場所の近くの歯と唇の赤みの中間にした（歯の側は白い所ほど重く数える。淡い歯ぐきに引っぱられない）。影で赤く写った右側の歯も残る。
- 副作用を見つけて直した: 明るい歯ぐき（IMG_9471）が歯に入る → 歯の側の重みで解決 / 暗い舞台（IMG_9296）で口の端の唇が歯になる → 暗い写真では影の歯を探さない / 口の端の影の小さな縁（IMG_9516 の 9 人目）→ ごく小さなかたまりは口の中にしっかり入っている時だけ残す。
- 「暗い写真」の判定（境目を唇寄りにする `low`）は、赤みの差だけでなく肌の明るさ 70 未満も条件にした（IMG_9516 の左端が誤って暗い写真扱いになっていた）。IMG_9360・9433 はクラウドに無いので、この変更では見ていない。

## 歯ぐき（2026-10-25、クラウド）
- ユーザーの指摘: 歯ぐきを唇とみなして、リップの色が歯ぐきにのる（IMG_9471 の 2 人とも）。「唇がガタガタの人はいない」も手がかりにしてほしい。
- 歯ぐきの色を別に覚える（5 つ目の分類）: 上の歯のすぐ上で、唇の色の分布からはっきり外れた赤い所を種にする。種が少なければ歯ぐきなし。
  - 日の当たった細い上唇は歯ぐきと同じような色になる（IMG_9471 の 1 人目の右側）。上から（下唇は下から）たどって、肌の次に出てくる赤い所は唇とする。
- 上唇の下の縁は、なめらかな線として選ぶ（`smoothUpperLip`。数列おきの点を結ぶ折れ線を動的計画法で。曲がり方に罰）。唇の下側の影が終わって明るくなる所を手がかりにする。縁より下の唇は消す（足すことはしない）。
- 13 人分の口で前後を比べ、閉じた口・暗い舞台・小さな顔は変わらないことを確かめた。

## 唇の形を整える・明るくした写真の歯（2026-10-25、クラウド）
- ユーザーの指摘: 唇の範囲に歯ぐきが入る所や、ガタガタして唇が取られている所がある。テスト写真 42 人分の口で唇の範囲を見直した。
- 歯から外した「歯らしい色」の所（濡れた下唇のつや・淡い所）は、まわりの唇・肌・歯ぐきの割合に応じて戻す（下唇がえぐれない。IMG_9471 の 2 人目の右下）。
- 小さく、まわりがほとんど唇の歯のかたまり（下唇のつや）は歯から外す（IMG_9499）。
- `tidyLip`（上唇の縁を決める前に）: 唇から離れた小さなかたまりを外す（鼻の下の影など）→ 唇に囲まれた小さな穴を埋める（つや・しわ。歯の入った穴・口の端の奥の暗い所は埋めない。暗い穴は点のように小さい時だけ）→ 縁の細いくぼみを閉じる（クロージング、半径は唇の厚みの 6%。歯と口の奥の暗いすき間には足さない）。
- 「肌の次の赤い所は唇」の決まり: 肌との境目の数画素は色が混ざって唇に見えるので、唇の画素を数え始めるのを少し先にした。歯ぐきとされた細い上唇が途切れなくなった（IMG_9471 の 1 人目の右端、IMG_9490 の 3 人目）。歯ぐきを唇に戻すのは唇の厚みほどまで。
- 仕上がり確認で見つかった不具合: 暗い写真を明るくしてから歯をタップすると、口の端の暗い所と上唇が歯として白く（青っぽい灰色に）塗られる（IMG_9321・9348）。明るくした写真は肌が明るいので「暗い写真」扱いにならず、影の歯を探していた。
  - 歯の赤みが唇とあまり変わらない（歯と唇の緑÷赤の差が 0.15 未満）明るい写真は、明るくした暗い写真とみなし、影の歯・下の歯を探さず、歯の確かな所を口の中のいちばん明るい 3 割に絞る。境目を唇寄りにする `low` は、本当に暗い写真（肌の明るさ 70 未満）だけ。
  - 編集用の大きさ（長い辺 2048）と原寸の両方で確かめた。明るくした写真を作るには `scripts/lowlight-eval.mjs`（ノイズ軽減 50・明るさ補正 50）。
- 残り: 明るくした IMG_9321 は、口の中（舌）が唇と同じ色になり、唇の範囲に入る（前からそう）。IMG_9516 の 2 人目の下唇右端のくぼみは残る。

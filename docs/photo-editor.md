# てもとフォト（端末の中だけで完結する写真編集Webアプリ）

リポジトリのいちばん上の階層がアプリ本体です。写真を**アップロードせず**、ブラウザの中（GPU と IndexedDB）だけで編集する写真編集アプリです。

## 調査: 一般的な写真編集アプリの機能（2026年10月時点）

| アプリ | 特徴 | 出典 |
|---|---|---|
| Snapseed 4（Google） | 30以上のツール、フィルム風フィルター（ハレーション・ブルーム・粒子）、スマートマスク、HSL・かすみの除去、非破壊・まとめて編集、RAW 現像、遠近補正、ホワイトバランス。無料・広告なし | [APKMirror（Snapseed 4.0 の更新内容）](https://www.apkmirror.com/apk/google-inc/snapseed/) |
| Lightroom モバイル（Adobe） | ライト・カラー・効果のパネル、プリセット、マスク（AIの被写体・空・背景、手動のブラシ・線形・円形）、2026年は「Scene Enhance」で被写体ごとの自動マスク | [The Digital Story](https://thedigitalstory.com/2026/02/Lightroom-insane-Scene-Enhance-tool-photo-podcast.html)、[Adobe](https://www.adobe.com/sg/learn/lightroom-cc/web/ai-assisted-masking-lightroom-mobile) |

**分かったこと**
- 定番の機能は「フィルター＋強さ」「ライト（露光・コントラスト・ハイライト・シャドウ・白黒レベル）」「カラー（色温度・彩度・HSL・グレーディング）」「ディテール」「効果（周辺光量・粒子・フェード）」「切り抜き・傾き・遠近」「部分補正（ブラシ・線形・円形）」「修復」「文字・スタンプ」「書き出し」
- 2026年は「端末内で動くAI処理」「タイパ」が流れ。一方で**写真をクラウドに上げたくない**・**位置情報が漏れるのが怖い**という不安に応える専用アプリが別に存在している
- 無料アプリの不満は「書き出しの画質・透かし（ウォーターマーク）」（appmatch の記事）

**RAW について**: DNG（iPhone・Android のスマホ、Adobe の変換、Leica・Pentax など）は RAW データそのものを現像します（非圧縮・可逆JPEG圧縮、タイル、黒/白レベル、AsShotNeutral のホワイトバランス、ColorMatrix による色変換、Malvar–He–Cutler のデモザイク、Orientation）。Canon・Nikon・Sony・Fujifilm などの独自 RAW は、[LibRaw](https://www.libraw.org/)（libraw-wasm 1.6.0 を `vendor/libraw/` に同梱。別スレッドの Worker で動き、同じサイトのファイルしか読まない）で RAW データを読み、撮影時のホワイトバランスで 16bit・リニア・Rec.2020 の画素にします。そこからの仕上げは `rawdev.js` で行います: 書き出す色空間（Display P3 / sRGB）への変換、明るさの自動調整（明るい方から1%の所を基準に）、白飛びの手前でなめらかに飽和させる肩、カメラの JPEG に近いゆるい S 字のトーン、ノイズ除去（色の成分は少しぼかし、明るさの成分は平方根の上でガイデッドフィルターにより平らな所だけをならす。ノイズの量は写真ごとに、小さな区画のうち平らなものの「2画素離れた画素との差」から測り、暗い所ほど強める。ぽつんとした1画素のノイズも除く）、シャープ（ノイズの量より小さな揺らぎは強めない）、暗部のつま先（ノイズの底を黒く・無彩色に沈める）、レンズの補正（色にじみ＝倍率色収差は、中心から外向きの輪郭で赤・青が緑からどれだけずれているかを測って色ごとの倍率で直す。周辺の暗さ・ゆがみは手動）。編集中は半分の大きさ（4画素を1つに。ノイズも減る）で現像し、書き出しでは元の大きさで DHT デモザイクにより現像し直します（5D Mark II の CR2 で約24秒）。16bit のデータを持っているので、「RAW の露出」（−3〜+3 EV）で白飛び・黒つぶれした所の階調を戻せます。

**16bit の細かさでの編集**: 現像した画像を 8bit に丸めたときの残り（−0.5〜0.5 段階）を別に GPU に送り、幾何パスで足し戻します。途中の画像は半精度の浮動小数点（RGBA16F）で持ち、最後に 8bit にするときに ±0.5 段階のディザを混ぜるので、トーンカーブなどで強く引き伸ばしても、空・背景・肌のグラデーションに縞（トーンジャンプ）が出ません。修復・美肌は 8bit の画像に当て、残りはそのまま足します（±0.5 段階より小さいので見た目に影響しない）。LibRaw で読めないもの・RAW データの入っていないものは、カメラが RAW の中に入れている JPEG を使います（情報パネルにどちらで開いたかを表示）。

**「同等以上」の部分**: 一般的なアプリの調整機能をほぼそろえたうえで、**写真を外に出さない**（ページの CSP で `connect-src 'none'`＝通信そのものを禁止）、**位置情報を確実に消す**、**モザイク・ぼかし**、**インストール不要**の4点で上回ります。足りないのは AI の自動マスク（被写体・空）です。

## しくみ

```
写真ファイル ──(createImageBitmap・EXIFの向きを反映)──▶ 元画像（最大 約1,670万画素）
   │                                                            │ 修復・モザイク（操作の一覧から毎回再現）
   ▼                                                            ▼
IndexedDB（元のファイル＋編集レシピ）              WebGL2: ① 幾何（切り抜き・回転・傾き・遠近）
                                                         ② 縮小してぼかす（明瞭度・ハイライト/シャドウ・ブルーム用）
                                                         ③ 色（WB・露光・トーン・部分補正・カーブ・HSL・グレーディング・効果）
                                                                      ▼
                                                   2D Canvas: フレーム（枠・角丸・余白） → 表示／書き出し
```

- **非破壊**: 保存するのは元のファイルと「編集レシピ」（`state.js`）だけ。修復やモザイクも操作の一覧として保存し、開くたびに元画像から再現する
- **プレビューと書き出しが一致**: ぼかし・粒子・シャープの量は「画像の大きさに対する割合」で決めているので、小さいプレビューと大きな書き出しで見た目が同じ
- **大きな写真**: iPhone の Safari の Canvas 上限（約1,670万画素）と GPU のテクスチャ上限に合わせて自動で縮める（12MP のスマホ写真はそのまま）
- **RAW**: `rawlib.js`・`rawdev.js`（LibRaw での読み込みと 16bit からの現像）、`raw.js`（TIFF の構造・DNG の現像・プレビューの取り出し）、`ljpeg.js`（可逆JPEG）、`raw-worker.js`（重い処理を別スレッドで）。12MP の DNG の現像は約1.3〜1.5秒（このパソコンの Node で計測）
- **グリッド**: `grid.js`（レイアウト定義・動かせる線（マスの境目をつながりごとに1本にまとめ、両側のマスが最小の大きさを保つ範囲で動かす）・マスの位置・写真の切り出し範囲・描画）
- **ファイル**: `state.js`（編集レシピと検証）・`geometry.js`（座標変換）・`engine.js`（WebGL2）・`curves.js`・`auto.js`・`presets.js`・`retouch.js`・`exif.js`・`compose.js`・`db.js`・`ui.js`・`app.js`

## スマホで快適に（2026-11-02、1.36.1。ブランチ `claude/project-thread-74ctqj`）
ユーザーの依頼「スマホで快適に精度よく動くように、目線移動以外の全ての機能を改善」。画面の作り直しは別のスレッドなので、ここでは仕上げの計算まわりだけ。
- **仕上げの結果がアプリの更新で消えない**（`calc-version.js`）: 前は保存した仕上がり（`hq:<id>`）・途中の段（`stage:<id>`）をアプリの版（VERSION）が違えば全部捨てていたので、更新のたびに開いた写真を一から（iPhone では数分）計算し直していた。
  今は段ごとの計算の版 `CALC = { ll, db, wh, cm, fa, bs, bk, mix }` を鍵（`stageKeys`・`hqKey`）に入れ、記録の形の版 `HQ_FMT` だけを確かめる。段の計算の結果が変わる直しをしたときは、その段の数を上げる。
  上げ忘れを防ぐため、段の計算に使うファイル（`scripts/calc-hashes.mjs` の STAGES から import でたどれるもの）の指紋を `tests/unit/calc-hashes.json` に記録し、変わるとテスト（`tests/unit/calc.test.js`）が止まる。直したら `npm run calc-hashes`（結果が変わるなら先に CALC を上げる）。
- **計算中に画面が消えない**（`wakelock.js`）: Screen Wake Lock を、仕上げ（`runLowlight`）と書き出しの間だけ取る。画面が消えると計算が止まり、iPhone では戻ったときにアプリが読み込み直されることがあった。隠れている間は取れないので、戻ったら取り直す。
- **残り時間**（`eta.js`）: 進み具合の最近 45 秒の進む速さから「あと約 2 分」を出す（仕上げの表示と書き出しの円）。段ごとに速さが違うので、段が変わるとしばらくして見積もりも変わる。
- **iPhone でもノイズ除去を WebAssembly で**（`restoration-lowlight.js` の `nlmRunner`）: 前は呼ぶたびに WebAssembly.Memory を作っていて iPhone・iPad では使えなかった（Safari はメモリごとに大きな番地の範囲を取る）。Worker ごとに 1 組を使い回し、足りなければ広げる。結果は JavaScript と 1 ビットも変わらない（テストあり。IMG_9348 の書き出しがバイト単位で同じ）。
- **全体 AI（くっきり）は人物の区画だけ**（`wholeai.js` の `tilesNeeded`・`wholeCovers`、`whole-worker.js` の need/done）: 全体 AI は仕上げでいちばん時間がかかる（クラウドの iPhone 相当で 128 秒）。くっきりの重みの地図を先に作り、重みが 0 でない所にかかる区画だけ動かす（70 区画 → 40〜55）。計算した区画（`done`）は差分と一緒に保存し、あとで顔 AI で全体に当てるときは残りだけ足す。
  あわせて、くっきりの重みが背景にも 1 割ほど残っていた（AI の人物の地図が背景でも 0.03〜0.1）のを、`crisp.js` の `BACK`（0.12 以下は 0）で直した（CALC.cm = 2）。
- **リップの色を照明に合わせる**（`brushfx.js` の `lipUnderLight`）: 舞台の橙の照明では、ピンク・ローズが紫に見えた。まわりの肌の色の比を日なたの肌の目安（`LIP_SKIN_REF`）と比べて照明の色とみなし、目標の色に 0.75 乗で掛ける（`LIP_ADAPT`）。照明の色が強いときだけで、日なたの写真では変わらない。
- 計測（4 コアのクラウド、iPhone として動かした IMG_9348、おまかせ → くっきり 50 → ぼかし → 顔 AI 1 つ → 書き出し）: 421 秒 → 390 秒（暗所補正 72 → 62 秒、顔 AI ありなので全体 AI は全区画）。実機の iPhone では確かめていない。
  区画の間引き（パソコンとして、IMG_9536 をくっきり 50 だけ）: 全体 AI 70 区画 101 秒 → 51 区画 83 秒。書き出した JPEG は全区画のときとバイト単位で同じ（背景の重みが 0 なので、計算しない区画は仕上がりに出ない）。
- 見送ったもの: iPhone の Worker を増やす・WebGPU を試す（過去にメモリ不足で落ちた経緯があるので、実機で確かめずには変えない）。美肌ナチュラルの「のっぺり」は、肌のきめの量（S/700〜S/90 画素の明るさの揺れの中央値）を測っても日なたと暗所で差がなく（3.9〜7.9）、自動で加減する決め手がなかったので、そのまま。

## セキュリティとプライバシー

| リスク | 対策 | テスト |
|---|---|---|
| 写真が外部に送られる | CSP `connect-src 'none'`（fetch・XHR・WebSocket が使えない）、外部スクリプトなし | E2E: ページが外部に1件も通信しないこと、CSP の値 |
| 位置情報などのメタデータが残る | 書き出しは Canvas から作り直すので Exif が入らない。読み込み時に位置情報があれば警告 | E2E: Exif（GPS・カメラ名）入りの JPEG を読み込み → 書き出したファイルに `Exif`・カメラ名が含まれない |
| 悪意のある画像ファイル・Exif | Exif 解析はすべて範囲チェック、IFD の循環を検出、件数上限 | 単体: 300回ランダムに壊したデータで例外なし |
| 読み込んだプリセット・保存データの改ざん | `validateState()` で型・範囲・件数・色の形式を直す（`__proto__` などのキーも拒否） | 単体: 不正な値・汚染・件数オーバー |
| 容量不足・データ消失 | `navigator.storage.persist()` を依頼、使用量を表示。保存に失敗したら知らせる | — |

# てもとフォト（端末の中だけで完結する写真編集Webアプリ）

リポジトリのいちばん上の階層がアプリ本体です。写真を**アップロードせず**、ブラウザの中（GPU と IndexedDB）だけで編集する写真編集アプリです。

## 調査: 一般的な写真編集アプリの機能（2026年10月時点）

| アプリ | 特徴 | 出典 |
|---|---|---|
| Snapseed 4（Google） | 30以上のツール、フィルム風フィルター（ハレーション・ブルーム・粒子）、スマートマスク、HSL・かすみの除去、非破壊・まとめて編集、RAW 現像、遠近補正、ホワイトバランス。無料・広告なし | [APKMirror（Snapseed 4.0 の更新内容）](https://www.apkmirror.com/apk/google-inc/snapseed/) |
| Lightroom モバイル（Adobe） | ライト・カラー・効果のパネル、プリセット、マスク（AIの被写体・空・背景、手動のブラシ・線形・円形）、2026年は「Scene Enhance」で被写体ごとの自動マスク | [The Digital Story](https://thedigitalstory.com/2026/02/Lightroom-insane-Scene-Enhance-tool-photo-podcast.html)、[Adobe](https://www.adobe.com/sg/learn/lightroom-cc/web/ai-assisted-masking-lightroom-mobile) |
| VSCO・LINE Camera・Picsart・Canva | フィルター重視（VSCO）、スタンプ3万種・コラージュ（LINE Camera）、文字入れ・SNS画像（Canva・Picsart） | [arekore.app](https://arekore.app/hobby/iphone-photo-editing-apps)、[appmatch](https://appmatch.jp/app-i0rhc9-app-rec-lite-2026/) |
| Exif 削除アプリ（PhotoMapper など） | 写真の位置情報（数メートルの精度）を、SNSに載せる前に消す | [imageupload.io](https://imageupload.io/blog/exif-data-privacy-risk-how-to-remove-metadata-from-photos)、[App Store](https://apps.apple.com/us/app/-/id1347742014) |

**分かったこと**
- 定番の機能は「フィルター＋強さ」「ライト（露光・コントラスト・ハイライト・シャドウ・白黒レベル）」「カラー（色温度・彩度・HSL・グレーディング）」「ディテール」「効果（周辺光量・粒子・フェード）」「切り抜き・傾き・遠近」「部分補正（ブラシ・線形・円形）」「修復」「文字・スタンプ」「書き出し」
- 2026年は「端末内で動くAI処理」「タイパ」が流れ。一方で**写真をクラウドに上げたくない**・**位置情報が漏れるのが怖い**という不安に応える専用アプリが別に存在している
- 無料アプリの不満は「書き出しの画質・透かし（ウォーターマーク）」（appmatch の記事）

**RAW について**: DNG（iPhone・Android のスマホ、Adobe の変換、Leica・Pentax など）は RAW データそのものを現像します（非圧縮・可逆JPEG圧縮、タイル、黒/白レベル、AsShotNeutral のホワイトバランス、ColorMatrix による色変換、Malvar–He–Cutler のデモザイク、Orientation）。Canon・Nikon・Sony・Fujifilm などの独自 RAW は、[LibRaw](https://www.libraw.org/)（libraw-wasm 1.6.0 を `vendor/libraw/` に同梱。別スレッドの Worker で動き、同じサイトのファイルしか読まない）で RAW データを読み、撮影時のホワイトバランスで 16bit・リニア・Rec.2020 の画素にします。そこからの仕上げは `rawdev.js` で行います: 書き出す色空間（Display P3 / sRGB）への変換、明るさの自動調整（明るい方から1%の所を基準に）、白飛びの手前でなめらかに飽和させる肩、カメラの JPEG に近いゆるい S 字のトーン、色ノイズ除去（明るさの成分は残して色の成分だけぼかす）、暗部のつま先（ノイズの底を黒く・無彩色に沈める）。編集中は半分の大きさ（4画素を1つに。ノイズも減る）で現像し、書き出しでは元の大きさで DHT デモザイクにより現像し直します（5D Mark II の CR2 で約15秒）。16bit のデータを持っているので、「RAW の露出」（−3〜+3 EV）で白飛び・黒つぶれした所の階調を戻せます。LibRaw で読めないもの・RAW データの入っていないものは、カメラが RAW の中に入れている JPEG を使います（情報パネルにどちらで開いたかを表示）。

**「同等以上」の部分**: 一般的なアプリの調整機能をほぼそろえたうえで、**写真を外に出さない**（ページの CSP で `connect-src 'none'`＝通信そのものを禁止）、**位置情報を確実に消す**、**モザイク・ぼかし**、**インストール不要**の4点で上回ります。足りないのは AI の自動マスク（被写体・空）です。

## しくみ

```
写真ファイル ──(createImageBitmap・EXIFの向きを反映)──▶ 元画像（最大 約1,670万画素）
   │                                                            │ 修復・モザイク（操作の一覧から毎回再現）
   ▼                                                            ▼
IndexedDB（元のファイル＋編集レシピ）              WebGL2: ① 幾何（切り抜き・回転・傾き・遠近）
                                                         ② 縮小してぼかす（明瞭度・ハイライト/シャドウ・ブルーム用）
                                                         ③ 色（WB・露光・トーン・部分補正・カーブ・HSL・グレーディング・効果）
                                                                      ▼
                                                   2D Canvas: フレーム・文字・スタンプ・手描き → 表示／書き出し
```

- **非破壊**: 保存するのは元のファイルと「編集レシピ」（`state.js`）だけ。修復やモザイクも操作の一覧として保存し、開くたびに元画像から再現する
- **プレビューと書き出しが一致**: ぼかし・粒子・シャープの量は「画像の大きさに対する割合」で決めているので、小さいプレビューと大きな書き出しで見た目が同じ
- **大きな写真**: iPhone の Safari の Canvas 上限（約1,670万画素）と GPU のテクスチャ上限に合わせて自動で縮める（12MP のスマホ写真はそのまま）
- **RAW**: `rawlib.js`・`rawdev.js`（LibRaw での読み込みと 16bit からの現像）、`raw.js`（TIFF の構造・DNG の現像・プレビューの取り出し）、`ljpeg.js`（可逆JPEG）、`raw-worker.js`（重い処理を別スレッドで）。12MP の DNG の現像は約1.3〜1.5秒（このパソコンの Node で計測）
- **グリッド**: `grid.js`（レイアウト定義・動かせる線（マスの境目をつながりごとに1本にまとめ、両側のマスが最小の大きさを保つ範囲で動かす）・マスの位置・写真の切り出し範囲・描画）
- **ファイル**: `state.js`（編集レシピと検証）・`geometry.js`（座標変換）・`engine.js`（WebGL2）・`curves.js`・`auto.js`・`presets.js`・`retouch.js`・`exif.js`・`compose.js`・`db.js`・`ui.js`・`app.js`

## セキュリティとプライバシー

| リスク | 対策 | テスト |
|---|---|---|
| 写真が外部に送られる | CSP `connect-src 'none'`（fetch・XHR・WebSocket が使えない）、外部スクリプトなし | E2E: ページが外部に1件も通信しないこと、CSP の値 |
| 位置情報などのメタデータが残る | 書き出しは Canvas から作り直すので Exif が入らない。読み込み時に位置情報があれば警告 | E2E: Exif（GPS・カメラ名）入りの JPEG を読み込み → 書き出したファイルに `Exif`・カメラ名が含まれない |
| 悪意のある画像ファイル・Exif | Exif 解析はすべて範囲チェック、IFD の循環を検出、件数上限 | 単体: 300回ランダムに壊したデータで例外なし |
| 読み込んだプリセット・保存データの改ざん | `validateState()` で型・範囲・件数・色の形式を直す（`__proto__` などのキーも拒否） | 単体: 不正な値・汚染・件数オーバー |
| 文字入れによる XSS | 文字は Canvas に描くだけ（DOM に入れない）。UI は `h()`（textContent） | E2E: `<img onerror>` を入力しても実行されない |
| 容量不足・データ消失 | `navigator.storage.persist()` を依頼、使用量を表示。保存に失敗したら知らせる | — |

## RAW とグリッドのテスト

- 単体（`tests/unit/raw.test.js`）: テスト用に DNG を組み立て（非圧縮・可逆JPEG・タイル・ベイヤー配列4種・黒/白レベル・WB・色変換行列・露出補正・向き）、現像した色が元の色と一致すること。プレビュー入りの TIFF 型 RAW（NEF 風）、独自形式（CR3 風）から一番大きい JPEG を取り出すこと（可逆JPEGは除く）。可逆JPEGの符号化→復号。壊れたファイル150通りで固まらないこと
- 単体（`tests/unit/grid.test.js`）: 29種類のレイアウトが重ならず・はみ出さず・すき間なく埋まること、すき間・余白の計算、写真の切り出し範囲
- E2E（`tests/e2e/photo-raw.spec.js`・`photo-grid.spec.js`）: DNG を開いて色が正しい・再読み込みしても開ける・書き出せる、NEF の向き、CR3、対応外の RAW の案内、LibRaw での現像（半分の大きさで編集・RAW の露出・元の大きさで書き出し）、LibRaw で読めない CR3 はプレビューで開く。単体（`tests/unit/rawdev.test.js`）: 灰色が灰色のまま・一部ずつ現像しても同じ・明るさの自動調整と RAW の露出・暗部のノイズが色の粒にならない。グリッドは単色の写真4枚で、マスごとの色・すき間の色・レイアウト変更・入れ替え・ドラッグ・拡大・線のドラッグ（表示と書き出しの両方・端で止まる・元に戻す）・書き出しの大きさ・一覧への保存・a11y

## 実機で確かめること

- 本物のカメラの RAW（このセッションでは用意できず、組み立てたファイルで確認）: iPhone の ProRAW（新しい iOS は JPEG XL 圧縮のことがあり、その場合はプレビューを使う）、Android の DNG、各メーカーの RAW のプレビューの大きさ。LibRaw の現像は、本物の Canon 5D Mark II の CR2 と Sony FX30 の ARW で、カメラの JPEG と見比べて確認（CR3 の実ファイルは未確認）

- iPhone の Safari での WebGL2 の速さと、大きな写真（12MP）の書き出しにかかる時間
- HEIC（iPhone の標準形式）の読み込み（Safari は対応、Chrome・Edge は非対応 → 案内を表示）
- 実際の写真でのスポット修復の自然さ、自動補正の効き具合
